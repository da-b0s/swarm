Key design decisions on the nonce:

The nonce is `keccak256(abi.encode(address(this), dealId, buyer, salt))` where `salt` is a buyer-supplied bytes32. The struct the buyer signs is the standard EIP-3009 `ReceiveWithAuthorization` with `to = address(this)` (the pool). Because `receiveWithAuthorization` requires `msg.sender == to`, only the pool can call `USDC.receiveWithAuthorization` — nobody else can invoke it. The `nonce` passed to USDC is the one we derived, so a replayer cannot reuse the same authorization for a different deal: changing `dealId` changes the nonce, which changes the `ReceiveWithAuthorization` struct hash, which invalidates the signature. A relayer cannot redirect a commit because: (1) the USDC destination `to` is the pool address (not a free parameter the relayer controls), (2) only the pool can call `receiveWithAuthorization` (payee check), and (3) the nonce binds the pool address + dealId + buyer, so the signature cannot be replayed on a different deal even at the same pool.
